To find the CIDR range (IP address range) of a particular GKE cluster, use these commands.

### 1. Find the cluster's Pod and Service CIDR ranges

```
gcloud container clusters describe CLUSTER_NAME \
  --region REGION \
  --project PROJECT_ID \
  --format="yaml(clusterIpv4Cidr,servicesIpv4Cidr,ipAllocationPolicy)"
```

Replace `CLUSTER_NAME`, `REGION`, and `PROJECT_ID` with your values.

### 2. Find CIDR ranges using kubectl

First, switch to the correct cluster context:

```
kubectl config current-context
```

Find Pod CIDR ranges allocated to nodes:

```
kubectl get nodes -o custom-columns=NODE:.metadata.name,POD_CIDR:.spec.podCIDR
```

Find Pod CIDR ranges for all nodes:

```
kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.podCIDR}{"\n"}{end}'
```

### 3. Find the cluster's subnet and secondary IP ranges

```
gcloud compute networks subnets describe SUBNET_NAME \
  --region REGION \
  --project PROJECT_ID \
  --format="yaml(ipCidrRange,secondaryIpRanges)"
```

### Important distinction

| CIDR type            | Purpose                                      |
| -------------------- | -------------------------------------------- |
| Node subnet CIDR     | IP addresses assigned to GKE nodes           |
| Pod CIDR             | IP addresses assigned to Pods                |
| Service CIDR         | Internal Kubernetes Service IP addresses     |
| Cloud NAT public IPs | Outbound source IPs seen by external systems |

One question: Are you trying to find the Pod CIDR, Node CIDR, Service CIDR, or Cloud NAT outbound IP range for your GKE cluster?

These are different, especially if you're finding source IPs for a firewall or SMTP relay request.
