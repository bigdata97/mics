How can you test it yourself?
Open Chrome DevTools → Network, enter a logo code, and inspect the API request.
Check for an OPTIONS preflight request and whether the response includes the expected CORS headers.
You can also test the preflight using curl:
curl -i -X OPTIONS \
  'https://<apigee-hostname>/<logos-endpoint>' \
  -H 'Origin: https://dev.mics.cvshealth.com' \
  -H 'Access-Control-Request-Method: GET' \
  -H 'Access-Control-Request-Headers: authorization,content-type'


A successful preflight should return a 2xx status and appropriate headers, such as:
Access-Control-Allow-Origin: https://dev.mics.cvshealth.com
Access-Control-Allow-Methods: GET, OPTIONS
Access-Control-Allow-Headers: Authorization, Content-Type


If the preflight fails, inspect the response status and headers. An HTTP 401, 403, 404, or 400 may indicate that routing, authentication, or security policies are rejecting the OPTIONS request before CORS handling completes.
